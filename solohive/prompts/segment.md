# Задание: нарезка документа на отдельные требования (пчела-нарезчик)

Документ ниже дан с номерами строк в формате «Lнн| текст». Выдели из него все отдельные требования — утверждения о том, что система, данные, интерфейс, интеграция, API или процесс должны делать или обеспечивать, — а также критерии приёмки.

Правила нарезки:
1. Если у пункта в документе есть собственный номер (Ф-1, НФТ-2, FR-3 и т. п.), то один номерной пункт = одно требование, doc_id = этот номер. Не дроби номерной пункт — неатомарность оценит рецензент.
2. Если номера нет — выделяй смысловые требования: одно предложение, пункт списка или строка таблицы с правилом = одно требование; doc_id = null. Если раздел использует локальную нумерацию (1., 2., 3.), укажи doc_id в виде «<раздел> п. N», например «Логика работы метода п. 2».
3. Включай: цели (kind=goal), архитектуру и потоки (architecture), UI (ui), бизнес-процесс/BPMN (process), функциональные (functional), нефункциональные (nonfunctional), требования к данным (data), интеграции (integration), API — метод и авторизацию, шаги логики, особые правила, параметры запроса, поля ответа, коды ответов с телами (api) — и критерии приёмки (acceptance, каждая строка таблицы отдельно).
4. Не включай: служебные поля паспорта документа (JIRA, роли владельцев, тип работы), пункты шаблонного чек-листа ревью, пустой блок согласующих, заголовки и пустые разделы — их оценивает системный аналитик на уровне набора.
5. API: каждый параметр запроса — отдельное требование; поля ответа можно объединить одним требованием на таблицу; каждый код ответа вместе с его телом — отдельное требование.
6. quote — ДОСЛОВНЫЙ фрагмент из документа без префикса «Lнн|», достаточный для понимания требования; для строки таблицы — текст ячеек через « | ». line_start / line_end — номера строк фрагмента.
7. summary — краткая нейтральная формулировка того, что требуется (до 15 слов).
8. section — путь раздела через « › », например «Часть A › Функциональные требования».
9. Сохраняй порядок следования требований в документе. Ничего не пропускай: лучше выделить лишнее требование, чем потерять настоящее.
